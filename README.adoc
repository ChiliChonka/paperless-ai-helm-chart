= paperless-ai Helm Chart

Helm chart to deploy **https://github.com/clusterzx/paperless-ai[paperless-ai]** on Kubernetes.

> **Important:** paperless-ai is not a typical stateless 12-factor app. It uses a first-start web wizard and stores state locally (SQLite + config files). This chart is designed accordingly.


== Features

* StatefulSet deployment with persistent storage
* Security contexts with sensible defaults
* Resource limits configured out of the box
* Startup, liveness, and readiness probes
* Ingress support with TLS
* Optional NetworkPolicy for security hardening
* Optional Prometheus ServiceMonitor
* JSON Schema for IDE autocompletion


== Important Limitations

=== Single replica only (replicas=1)
paperless-ai stores its configuration and state in a local SQLite database (and related config files).
Running multiple replicas would either create multiple independent instances or cause SQLite locking/corruption issues.

**This chart is intended to run with exactly one replica.**

=== Persistent storage required
Your configuration and state must survive pod restarts.
This chart persists **`/app/data`** using a PVC.

=== First start requires Web Wizard
On first start you must complete the setup wizard in the web UI.
After that, the configuration/state stays on the persistent volume.

=== Kubernetes service env injection can break startup
Kubernetes can inject `*_SERVICE_HOST` / `*_SERVICE_PORT` environment variables into pods.
paperless-ai (or its runtime) may accidentally interpret these and try to bind to the Service ClusterIP which can crash with errors like:

`Error: bind EACCES tcp://10.x.x.x:3000`

**This chart sets `enableServiceLinks: false` by default to prevent this issue.**


== Requirements

- Kubernetes: v1.25+ (recommended)
- Helm: v3.8+
- A default StorageClass (or configure `persistence.storageClassName`)


== Quick Start

=== Install

[source,shell]
----
helm install paperless-ai oci://ghcr.io/chilichonka/charts/paperless-ai \
  --namespace paperless-ai --create-namespace
----

=== Upgrade

[source,shell]
----
helm upgrade --install paperless-ai oci://ghcr.io/chilichonka/charts/paperless-ai \
  --namespace paperless-ai --create-namespace
----

=== With custom values

helm upgrade --install paperless-ai oci://ghcr.io/chilichonka/charts/paperless-ai \
  --namespace paperless-ai \
  -f my-values.yaml

helm show values oci://ghcr.io/chilichonka/charts/paperless-ai > paperless-ai-values.yaml

== Backup and Restore

=== Backup

paperless-ai stores all data in `/app/data`. To backup:

[source,shell]
----
# Create a backup of the PVC
kubectl exec -n paperless-ai paperless-ai-0 -- tar czf - /app/data > backup.tar.gz

# Or use your storage provider's snapshot feature
----

=== Restore

[source,shell]
----
# Stop the pod first (scale to 0 is not possible with StatefulSet managing PVC)
# Then restore the data
kubectl exec -n paperless-ai paperless-ai-0 -- tar xzf - -C / < backup.tar.gz
----


== Troubleshooting

=== Pod fails to start with EACCES error

If you see errors like `Error: bind EACCES tcp://10.x.x.x:3000`:

1. Ensure `enableServiceLinks: false` is set (default in this chart)
2. Check if any other services might inject conflicting environment variables

=== Pod stuck in Pending

1. Check if PVC can be provisioned: `kubectl describe pvc -n paperless-ai`
2. Verify StorageClass exists or set `persistence.data.storageClassName`

=== Cannot access web UI

1. Check pod status: `kubectl get pods -n paperless-ai`
2. Check logs: `kubectl logs -n paperless-ai paperless-ai-0`
3. Port-forward for direct access: `kubectl port-forward -n paperless-ai svc/paperless-ai 3000:3000`
